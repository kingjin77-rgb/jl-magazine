# 이미지 운용 규칙

제안서에 들어가는 이미지를 **증거·실체 이미지**와 **보조 이미지**로 나누고, 각각의 조달·처리 범위를 고정한다. 이 구분을 지키지 않으면 제안서 전체의 신뢰가 무너진다.

---

## 1. 구분표

| 구분 | 해당 이미지 | 조달 | AI 생성 | 스톡 사진 |
|---|---|---|---|---|
| **증거·실체** | 하자 현장 사진, 단지 전경·조감도, 법인 로고, 변호사 프로필 사진, 판결문·공문 캡처 | **실물만** | **금지** | **금지** |
| **보조** | 표지 배경 텍스처, 간지 배경, 아이콘, 도해·차트, 추상 그래픽 | 코드 렌더링 우선, 필요 시 스톡 | 조건부 허용 | 허용 |

### 왜 이렇게 나누는가

- 하자 사진은 **증거 성격**이다. 실제 하자와 다른 이미지를 넣으면 허위 표시가 된다.
- 단지 전경을 다른 아파트 사진이나 생성 이미지로 채우면, 입주민이 자기 단지가 아님을 즉시 알아본다. 제안서 전체가 성의 없어 보인다.
- 변호사 사진은 실존 인물의 초상이다. 생성 이미지로 대체할 수 없다.
- 반면 표지 배경의 추상 패턴에는 이런 문제가 없다.

## 2. 증거·실체 이미지 — 허용되는 처리

수령한 원본에 대해 **아래까지만** 한다.

| 처리 | 허용 | 비고 |
|---|---|---|
| 크롭 (구도 정리) | O | 하자 부위가 잘리지 않는 범위 |
| 밝기·대비 보정 | O | 어두워서 안 보이는 사진에 한함. 하자를 과장하는 방향의 보정 금지 |
| 리사이즈 | O | 인쇄 해상도 이상 유지 |
| 해상도 향상 (upscale) | 조건부 | 로고·저해상 사진에 한함. **하자 사진에는 적용하지 않음** — 없던 디테일이 생성될 수 있음 |
| 배경 제거 | 조건부 | 변호사 프로필 사진의 배경 정리에 한함 |
| 리터치·보정 | **금지** | 인물의 얼굴·형태 변형, 하자 사진의 내용 변경 일체 |
| 합성 | **금지** | |

### 하자 사진 캡션 필수

모든 하자 사진에는 캡션을 단다. 캡션 없는 하자 사진은 제안서에 넣지 않는다.

```
103동 1502호 거실 천장 균열 (2026.08.10 촬영)
```

- 위치(동·호수 또는 공용부 위치) + 하자 내용 + 촬영일
- 촬영일이 확인되지 않으면 `[촬영일 미확인]`으로 표기한다. 추정 날짜를 쓰지 않는다.

## 3. 보조 이미지 — 조달 순서

1. **코드 렌더링 우선** — 도해·차트·타임라인·아이콘은 SVG/HTML로 직접 그린다. 팔레트가 정확히 맞고, 수정이 자유롭고, 라이선스 문제가 없다. 제안서 그래픽 5종은 전부 여기 해당한다.
2. **스톡 사진** — 표지 배경 등 실사가 필요한 경우. magnific `stock_search` / `stock_download` 사용.
3. **AI 생성** — 위 둘로 안 되는 추상 배경에 한해. 사람·건물·문서처럼 **실체로 오인될 수 있는 대상은 생성하지 않는다.**

### 스톡 사용 시

- 제안서 말미에 이미지 출처를 표기한다.
- 아파트 외관 스톡 사진을 **표지에 크게** 쓰지 않는다. 대상 단지로 오인된다. 쓰더라도 추상적으로 처리하거나 작게 배치한다.

## 4. 사용할 도구 (이미 연결되어 있음)

| 용도 | 도구 |
|---|---|
| 실물 이미지 수령 | Google Drive — `download_file_content` |
| 저해상 로고·자료 보정 | magnific — `images_upscale` |
| 프로필 사진 배경 정리 | magnific — `images_remove_background` |
| 실사 스톡 검색·수급 | magnific — `stock_search` / `stock_download` |
| 브랜드킷·디자인 자산 | Canva |
| 디자인 시스템 (필요 시) | Figma |

**추가로 설치할 MCP는 없다.** 이미지 관련 병목은 도구 부족이 아니라 "실물 파일이 세션까지 도달하는 경로"였고, 이는 구글드라이브 브리지로 해소된다.
