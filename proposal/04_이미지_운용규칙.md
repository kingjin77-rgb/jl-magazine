# 이미지·그래픽 운용 규칙

기본제안서는 매번 재사용되므로 **"한 번 만들고 계속 쓰는 것"과 "매번 바꾸는 것"을 분리**한다.

---

## 1. 이미지 3계층

| 계층 | 대상 | 확보 | 교체 주기 | 현재 |
|---|---|---|---|---|
| **1. 법인 자산** | 로고, 변호사 5인 프로필, 사무실 전경, 자격증·보험증서·전문분야 등록증 | 실물 1회 | 영구 | **미확보** |
| **2. 하자 사례** | 월패드 / 타일 / 방수 / 방화문 — 유형별 3~5장 | JL 수행 단지 **실물** 아카이빙 | 사례 추가 시 누적 | **미확보** |
| **3. 단지별** | 표지 전경, 해당 단지 하자 현장 | 매 단지 수령 | 매번 | 단지 확정 후 |

**계층 2가 승부처다.** PART 3(S14~S17)이 "우리는 이런 하자를 찾아낸다"를 증명하는 구간인데 사진 없이는 성립하지 않는다. 그리고 **생성·스톡으로 대체 불가** — 하자 사진은 증거 성격이라 가짜를 쓰면 제안서 전체가 무너진다.

### 계층 2 사진 처리 — 반드시 지킨다

- **단지 식별정보 마스킹 필수.** 타 의뢰인의 하자 정보를 다른 단지 제안서에 그대로 노출하면 비밀유지 문제가 된다
  `103동 1502호 거실 천장 균열` → `○○아파트 세대 거실 천장 균열`
- **촬영일은 유지한다.** 단지명만 가리고 날짜는 남긴다
- 인터로 공동 수행 건 사진이면 JL 단독 제안서 사용 가부를 먼저 확인한다

### 사진을 세션까지 가져오는 방법

PPTX 안의 이미지는 파일 용량 때문에 내가 직접 못 뽑는다. 로컬에서 추출해 올려야 한다.

> **일괄 추출**: `.pptx` 확장자를 `.zip`으로 바꿔 압축을 풀면 `ppt/media/` 폴더에 그 파일의 이미지가 **전부 원본 해상도로** 들어 있다. 하자 사진만 골라 드라이브 `D3_하자사진/`에 업로드.

## 2. 실물만 쓰는 것 / 만들어도 되는 것

| 구분 | 해당 | AI 생성 | 스톡 |
|---|---|---|---|
| **증거·실체** | 하자 현장 사진, 단지 전경, 로고, 변호사 사진, 판결문·공문 캡처 | **금지** | **금지** |
| **도해·그래픽** | 타임라인, 플로우, 차트, 단면 모식도, 아이콘 | 허용 (코드 우선) | — |
| **분위기** | 표지 배경 텍스처, 간지 | 조건부 | 허용 |

**아파트 외관을 3D 렌더링이나 스톡으로 표지에 크게 쓰지 않는다.** 실제 단지가 아님을 입주민이 즉시 알아보고, 하자 사진 옆에 있으면 "이것도 만든 것 아니냐"는 의심을 부른다. 법무법인 제안서에서 가장 위험한 것이 신뢰 훼손이다.

## 3. 그래픽 제작 도구 배분

요소마다 맞는 도구가 다르다. **원칙: 도해·차트는 코드로 직접 그린다.** 팔레트가 정확하고, 수정이 자유롭고, 라이선스 문제가 없다.

| 요소 | 도구 | 이유 |
|---|---|---|
| 전체 아트보드·레이아웃 | **Claude Design** (`design` 스킬) | 클릭 선택·속성 패널·인라인 편집, PNG/PDF export |
| 타임라인 ① · 채권양도 ② · 절차 플로우 ③ · 비용 흐름 ⑤ | **인라인 SVG 직접 작성** | 팔레트 정확, 수치 정확, 수정 자유 |
| 하자 집계 차트 ④ | **SVG** (`dataviz` 기준 적용) | |
| **하자 단면 모식도 ⑥** | **SVG 직접 작성** | 치수를 정확히 넣어야 한다. 생성 이미지는 치수가 틀어진다 |
| 아이콘 | SVG 직접 또는 벡터 생성 | |
| 표지 배경 추상 그래픽 | 생성 또는 CSS | 실체를 그리지 않는 한도 |

### 3D 생성에 대한 판단

3D 모델 생성(`models3d_generate`)과 이미지 생성 도구가 연결되어 있지만, **이 제안서에서 3D의 실익은 거의 없다.**

- 아파트 외관·조감도 3D → **쓰지 않는다** (위 2항)
- 하자 단면 모식도 → 3D보다 **SVG가 낫다.** 방수 두께 `기준 3mm vs 실측 1.82mm`처럼 **치수가 핵심인 도해**인데, 생성 모델은 치수를 정확히 못 낸다
- 표지 배경 추상 그래픽 정도가 유일하게 고려할 만한 용도

즉 **도구를 섞어 쓰는 것 자체는 맞지만, 3D는 이 제안서의 필요 요소가 아니다.** 도해는 SVG, 레이아웃은 Claude Design 조합이 정답이다.

| 처리 | 허용 | 비고 |
|---|---|---|
| 크롭 | O | 하자 부위가 잘리지 않는 범위 |
| 밝기·대비 보정 | O | 어두워서 안 보이는 경우만. **하자를 과장하는 보정 금지** |

| 배경 제거 | 조건부 | 변호사 프로필 배경 정리만 |
| 리터치·합성 | **금지** | |

## 5. 캡션 규칙

하자 사진에는 캡션을 반드시 단다. 캡션 없는 하자 사진은 제안서에 넣지 않는다.

```
○○아파트 세대 욕실 바닥 방수 두께 부족 (2025.08.10 촬영)
```

- 위치 + 하자 내용 + 촬영일. 단지명은 마스킹
- 촬영일 미확인이면 `[촬영일 미확인]`. 추정 날짜를 쓰지 않는다
- 모식도에는 **"모식도"** 캡션을 단다

## 6. 사진이 없을 때 — 설계에 반영

제안 시점에 단지 사진을 못 받는 경우가 흔하다. 기본제안서는 **사진 없이도 성립하도록** 만든다.

- **표지**: 단지 전경판 + **추상 그래픽판** 2종을 준비. `이미지.표지_단지전경`이 `null`이면 자동 전환
- **PART 3**: 사진 슬롯이 비면 단면 모식도가 그 자리를 채우는 레이아웃
- **고정 25장은 애초에 사진에 의존하지 않는다** — 도해·차트·표 중심
